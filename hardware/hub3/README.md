# hub3

XIAO ESP32-S3 (1x7 のピンソケット 2 個に挿す)、74HC138、20 ピン 1.0mm の FFC コネクタ 3 個を載せた 36 x 36 mm の 2 層基板 (片面実装、穴なし)。ER-PCBA5981-1 を 3 枚つなぎ、`lt7680_multi` の構成 3 (`-DNUM_BOARDS=3`) と同じ配線にする (`WIRING.md`)。

- J1 (LCD0、左の辺)、J2 (LCD1、上の辺)、J3 (LCD2、右の辺): Ckmtw F-FPC1M20P-B310 下接 (LCSC C132515)。口は基板の外を向き、基板の辺にそろう。J2 は上の辺の中央、J1 と J3 は J2 の帯 (奥行き 7.6 mm) より下で、下の辺まで
- J4、J5: XIAO 用の 1x7、2.54 mm のメスのピンソケット (XFCN PM254V-11-07-H85、LCSC C2832270、高さ 8.5 mm)。USB-C を下の辺 (FFC の無い辺) に向けて挿すと、右の列 J4 が XIAO の 1〜7 番 (D0〜D6、D0 が下)、左の列 J5 が 8〜14 番 (D7〜5V、5V が下)。XIAO 本体 (回路図の U2) は基板に載らず、手で挿す
- U1: 74HC138 (SOIC-16、LCSC C2674688)。XIAO の下の、ソケットの 2 列の間に置く。A, B, C = D0, D2, D6。基板 b の LCM_SCS は Yb、LCD_CS は Y(3+b)、Y6 と Y7 は空き
- C1 100nF (74HC138 の 3.3V)、C2 10uF (XIAO の 5V ピンのそば)。どちらも XIAO の下
- 取り付け穴は無い

大きさは、コネクタとソケットで決まる。横は J1 の奥行き 7.9 mm (コートヤード)、ソケット 2 列の外形 18.9 mm、J3 の奥行き 7.9 mm と、そのすき間で 36 mm。縦は J2 の帯 7.6 mm と J1、J3 の長さ 28 mm で 36 mm。XIAO の下に部品を入れないと、縦は約 39 mm になる。

## 作り方

すべてスクリプトから作る。回路図と基板を手で直したら、次に `make.py` を流すと上書きされる。

```sh
/usr/bin/python3 make.py    # 回路図、部品を置いた基板、ライブラリ (KiCad 10 の pcbnew モジュールを使う)
/usr/bin/python3 route.py   # Freerouting で配線し、GND のベタを塗る
./check.sh                  # ERC、DRC (回路図との突き合わせ込み)、test_hub3.py。どれも 0 件で通る
/usr/bin/python3 fab.py     # JLCPCB 用: build/fab/ にガーバーとドリルの zip、BOM、部品配置 (CPL)
```

- 部品と網の表は `make.py` の先頭にあり、回路図と基板の両方がそこから作られる
- `test_hub3.py` は `make.py` とは別に、`WIRING.md` の配線表から各パッドの網を確かめる
- Freerouting は Linux 向けの実行環境同梱版 (`freerouting-2.4.1-linux-x64.zip`) を `~/.local/share/freerouting/2.4.1/` に置いて使う。jar 単体は Java 25 が要る
- 配線するときは GND のベタを外し、GND も線で引いてからベタを戻す。ベタを残したまま渡すと、Freerouting は GND を引かず、表のベタが島に分かれる
- Freerouting は、`make.py` で作るたびに違う配線を返し、ときどき島や未接続を残したり、電源の線を FFC のパッドの手前で長く細らせたりする。`route.py` は、KiCad の DRC が 0 件で、+5V と +3V3 の 0.6 mm 未満の区間が合わせて 7.5 mm (FFC コネクタ 1 個あたり約 2.5 mm) 以下になるまで、最大 8 回やり直す。Freerouting は同じ DSN なら設定や網の順を変えても同じ結果を返すが、`make.py` が作るたびに部品の内部 ID が変わって DSN も変わるので、やり直すときは `make.py` から作り直す。1 回ごとに別のプロセスで動かす (pcbnew の SWIG は、同じプロセスで基板を読み直して編集すると落ちる)
- 部品配置 (CPL) とガーバーの原点は基板の左下の角。SOIC-16 と 1x7 のピンソケットは JLCPCB の 0 度が KiCad と 90 度ずれるので、CPL で 90 度補正している (`fab.py` の `JLC_ROTATION_OFFSET`、JLCPCB の確認画面で見つけた)。BOM と CPL は LCSC の番号がある部品 (U1、C1、C2、J1〜J5)。J4、J5 は挿入部品 (THT) なので、JLCPCB の組み立てで挿入部品を受けてもらう

## 発注の前に確かめること

実物 (rev B) では、下の 1 番の向きの判断は誤りだった。両端の接点が同じ面にあるケーブルでつなぐと、コネクタの n 番は ER-PCBA5981-1 の CON1 の 21-n 番につながる。テスターで、CON1 の GND (JP1 の 1 番) と XIAO の D4 (コネクタの 19 番、LCD_SCLK) が導通した。このまま電源を入れると、5V (コネクタの 3、4 番) が CON1 の 18 番 (LCD_DIN) と 17 番に入り、ER-PCBA5981-1 には GND が届かない。3.3V の網 (JP1 の 6 番) は信号線からの漏れで約 1.6V になり、LT7680 は応答しない (STSR=0xFF)。両端の接点が反対の面にあるケーブルを使うか、基板のコネクタの番号の並びを逆にする。

以下は発注前に書いた判断 (誤り)。

- FFC の 1 番の向き。この基板は「コネクタの n 番 = ER-PCBA5981-1 の CON1 の n 番」としている。根拠: 今つないでいる変換基板 (FPC-20P 1.0MM) のコネクタは C132515 と同じ下接で (本人の確認、2026-10-19)、1 番も口から見て同じ側 (口を上にして左) にある (写真のシルクの 10 と 20 の位置から読んだ)。その変換基板で、同じケーブル (両端の接点が同じ面) を使って「変換基板の j 番 = CON1 の j 番」で動いている。この対応はケーブルの引き回し (曲げ、折り返し、ねじり) では変わらない。ケーブルの片端を裏返して挿すと、接点がコネクタの接点に当たらず、どこにもつながらない (`../../WIRING.md`)。n 番が 21-n 番につながるのは、両端の接点が反対の面にあるケーブルを使ったときだけ
- C132515 のフットプリントは、JLCPCB の EasyEDA にある同じ部品のフットプリント (FPC-SMD_P1.00-20P_XJ-CLS) のパッドの数値で作った。JLCPCB の部品配置の確認画面で、J1〜J3 の向きを確かめる
- 74HC138 の電源は XIAO の 3.3V、FFC の VDD は XIAO の 5V (USB からそのまま)
