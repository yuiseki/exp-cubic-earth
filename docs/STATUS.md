# 四角い地球 大型版: 確認済みの事実 (2026-10-16 時点)

試行錯誤の経緯は含めない。確かめた事実だけを書く。経緯は `../WIRING.md` と `../tmp/` (非公開) にある。

## 構成

| 部品 | 型番 | 備考 |
|---|---|---|
| コントローラー | Seeed XIAO ESP32-S3 (Sense 無し、PSRAM 8MB) | MAC `68:EE:8F:4B:1E:84` |
| 表示コントローラー基板 | ER-PCBA5981-1 (Levetop LT7680A-R、SDRAM 内蔵) | 4 線 SPI で制御。目視で LT7680A-R を確認 |
| パネル | ER-TFT040-3 (4 インチ 480x480 IPS、ST7701S) | RGB は基板から、初期化は 3 線 SPI を XIAO から直接 |
| 電源 | XIAO の USB-C から 5V | 基板の VDD は 5V |

配線 (CON1 の番号 = 1mm 20 ピン変換基板の番号):

| CON1 | 信号 | XIAO |
|---|---|---|
| 1, 2 | GND | GND |
| 3, 4 | VDD | 5V |
| 5 | LCM_SCS | D0 |
| 6 | LCM_SDO | D9 (MISO) |
| 7 | LCM_SDI | D10 (MOSI) |
| 8 | LCM_SCLK | D8 (SCK) |
| 9 | BL_CONTROL | D3 |
| 11 | LCM_RESET | D1 (open drain + 内蔵プルアップ) |
| 16 | LCD_CS | D2 |
| 18 | LCD_DIN | D5 |
| 19 | LCD_SCLK | D4 |

基板について確かめたこと:

- LCM_RESET には基板上のプルアップが無い。XIAO 側で open drain + 内蔵プルアップにして High に保つ
- バックライトは出荷時 (J1 短絡) で外部信号 BL_CONTROL により点灯する
- LCD_DIN は書き込み専用で、パネルからの読み出しはできない
- パネルの RST は CON1 に出ていない。基板上の RC リセット (R9 10kΩ で基板の 3.3V へ、C27 1µF で GND へ、時定数 10ms) だけにつながっており、マイコンからは操作できない (メーカー回答、2026-10-16)
- メーカー推奨の電源投入手順は「電源投入後 20〜30ms 待って RC リセットの完了を待ち、それから ST7701S を初期化する」

## 動いているもの

### LT7680 (`lt7680_*`)

- SPI: モード 3 (0 と 2 も可、1 は不可)。1 語 16 クロック、先頭 8 ビットが 0x00 = レジスタ番号、0x80 = データ書き込み、0x40 = 状態読み出し、0xC0 = データ読み出し
- PLL と SDRAM の初期化、480x480 の表示タイミング設定、レジスタの書き込みと読み返し
- カラーバー、BTE の四角形塗りつぶし、前景色の設定
- 表示用メモリへの画素の書き込み (REG[04h] の memory data port に RGB565 リトルエンディアンを 64 バイトずつ) と読み返しの一致確認
- 480x480 の全面書き込みは、画素のバーストが SPI 1 MHz で約 4.1 秒、10 MHz で 776 ms (レジスタの読み書きは 1 MHz のまま、`-DPIXEL_SPI_HZ=10000000`)。10 MHz で地球の書き込みと白塗りを 10 回繰り返し、10 回とも正しく映った (LCD_CS をつないだ状態)
- 20 MHz では 588 ms。10 回繰り返して 10 回とも映った。全画素の読み返し (`#V`、1 MHz、約 15 秒) で照合すると、1、10、20 MHz のどれで書いても 23 万画素のうち 6〜8 画素で 1 ビットが 0 から 1 に化けていて、速さによる差は無い
- 読み返すたびに化けた画素が増える (2 回目で約 20〜40)。何も読まずに 90 秒置いても増えない (7 画素)。読み返しそのものが表示用メモリを乱している。読み返さない普段の使い方では、時間がたっても絵は崩れない
- LT7680 側は接続が確定してから一度も失敗していない

### パネル (ST7701S)

- 初期化はメーカーのデモ (`LCD_init.h`) の列を 3 線 9 ビット SPI でビットバンして送る (CS は 1 語ごと、CLK Low でデータを置き High で取り込ませる)
- 初期化用の LCD_DIN と LCD_SCLK は LT7680 の SPI と相乗りさせない (相乗りすると真っ黒のまま)
- 正常に映っている状態では、反転 (INVON/INVOFF)、ソフトリセット、初期化列の再送が効く

### 地球の描画 (`lt7680_earth`)

- NASA Blue Marble (2002) から QSC (Quadrilateralized Spherical Cube) の 1 面を 480x480 の RGB565 に変換し (`make_qsc_faces.py`、pyproj の `+proj=qsc`)、ヘッダ `earth_qsc480.h` として焼き込む
- 起動直後と、シリアル命令 `#E` の両方で、地球の面 (日本からオーストラリア) がパネルに映ることをカメラで確認した

### 山頂型モジュール 2 個で 6 面 (`lt7680_multi`、hub3)

- 1 モジュール = XIAO ESP32-S3 Sense + hub3 + LT7680 基板 3 枚。基板 0, 1, 2 が `#N` の A, B, C
- モジュール 1 (B8:F8:62:F8:DB:A0): 辺 A2:B1 B2:C1 C2:A1。A = 面 3 (アフリカ) 回転 0、B = 面 0 (日本) 回転 1、C = 面 4 (北極) 回転 2 (2026-10-29 の 4 度目の並び、ESP-NOW で割り当て)
- モジュール 2 (8C:BF:EA:8F:3F:38): 辺 A2:B1 B2:C1 C2:A1。A = 面 5 (南極) 回転 3、B = 面 2 回転 2、C = 面 1 回転 3 (2026-10-29 の 2 度目の並び)
- `#I` (リセットを掛けずに選んだ基板だけ初期化し直す) のあと、その基板に緑の筋が出て、描き直しても残った (2026-10-29、両モジュールで)。ESP-NOW で `#A` (LCM_RESET を全基板に掛けて初期化し直す) を送り、`#E` で描き直すと消えた。閉じた立方体の電源を抜かずに直せる
- 同じ日、閉じた立方体のモジュール 1 の基板 A だけ、`#A` のあとも画素 SPI 20MHz で描くと緑の筋が残った。`#S5` (5MHz) で描き直すと消えた (本人の目視)。このときは四角いモバイルバッテリーで動いていた。同じ夜、pi4-deck の USB 給電で再起動すると、20MHz のまま 3 面とも安定し、`#G` も 30fps (1 コマ 19.8ms、TIMEOUT 無し) で回った (本人の目視とシリアル)。20MHz の信号の問題ではなく、電源の電圧が下がっていたせいと読み直す
- モジュール 2 を丸いモバイルバッテリー (2500mAh) で動かすと、`#G` の描き換えが止まった (2026-10-29 に 2 回。止まっている間もマイコンは `#G` を最後まで回し、終わってから ESP-NOW の ping を返した)。pi5-deck の USB 給電に替えると問題なく動いた (本人の目視)。電源だけを替えた比較なので、丸い電池の 5V が負荷に追いつかないと読んでいる (電圧は測っていない)
- 2 個を合わせて、境目で海岸線がつながる立方体の地球になることを目で確認した (2026-10-29)
- 辺のつながりから面と回転を出す計算: 面の画像の辺の中点を `+proj=qsc` の逆変換で球の上の点にし、接する辺同士の点が一致する組み合わせを全部試す。モジュール 1 の実際の割り当てを再現し、モジュール 2 では 1 通りだけが合った

### 道具

- ビルド: `arduino-cli compile --fqbn esp32:esp32:XIAO_ESP32S3` (esp32 コア 3.3.12)
- 書き込み: pi5-deck に USB 接続し、esptool 5.3.1 で `--before usb-reset --after hard-reset write-flash 0x10000 <app.bin>`
- シリアル命令は `#` を先頭に付けた 1 文字 (`#E` 地球、`#K`/`#W` 黒/白で塗る、`#0` 初期化の流れを 1 回、`#r` 状態)。端末側は `stty raw -echo` にしないと XIAO の出力が命令として戻る
- 映っているかの判定は Web カメラで、白で塗った写真のパネル領域の明るさ (映っていれば 220 以上、黒や固まった画面は 150 以下) で行った。1 枚の色だけでは固まった画面と正常を取り違える

## 起動時にパネルが映るか

2026-10-16 夜、D2 と CON1 16 番 (LCD_CS) の間の線がつながっていないことが分かった。つなぐと、USB-C の電源投入でパネルが安定して映るようになった (lt7680_multi の既定ビルド、流れ 2 回で 5/5、本人の目視)。メーカー推奨どおりの最小の起動 (試験時の旗 `BOOT_MINIMAL`、今は既定で旗は無い: 電源投入から 30ms 待ち → LT7680 の初期化 → ST7701S の初期化 1 回 → 表示オン) でも映る (カメラ判定 3/3、抜いていた時間 2.2〜4.7 秒、本人の目視でも全回)。画素 20MHz と組み合わせて 4/4 (本人の目視)。2026-10-16 夜からこれが `lt7680_multi` の既定の起動 (電源投入から地球まで約 1 秒)。LCD_CS がつながっていないと、パネルの 3 線 SPI の CS は浮いたままになる。

いつから外れていたかは分かっていない。下の表と、それをもとにした「流れを 2 回行う」などの手順は、LCD_CS が浮いていた可能性がある時期の数字なので、つないだ状態で測り直すまでは根拠にしない。

### LCD_CS が浮いていた可能性がある時期の数字 (参考)

「流れ」= LT7680 のハードリセット → PLL/SDRAM → 表示オン → 塗りつぶし → パネルの SWRESET + 初期化列 ×2。

| 起動の種類 | 起動時の流れ | 結果 |
|---|---|---|
| XIAO だけのリセット (esptool、esp_restart) | 1 回 | 0/8 |
| XIAO だけのリセット (esptool) | 2 回 | 10/10 |
| USB-C の電源投入 | 2 回 | 0/3 (本人の目視) |
| USB-C の電源投入 | 1 回 | 0/3 (本人の目視) |
| USB-C の電源投入 | 0、5、10、20、40、80 秒に 1 回ずつ (診断版) | 最初の流れの直後だけ白が映り、5 秒目の流れ以降は黒 (カメラ、1 回) |

- 映っていない状態から、動作中にシリアル命令 `#0` (流れ 1 回) を送ると映る (直近 4/4)
- XIAO だけをリセットし、パネルに触らなければ表示は保たれる (10/10)
- 電源投入で毎回映る起動の流れは、まだ見つかっていない。機構も未解明
